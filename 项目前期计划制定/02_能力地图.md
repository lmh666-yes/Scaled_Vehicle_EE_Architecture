# 02 能力地图：做完这台车，你手上有什么

> 一句话：这个项目不是"做个车"，是四个能力的训练场 —— **PID 会调 / CAN 会诊断 / 电源管得住 / Linux 用得起来**。
> 每一项都写清楚：练什么、怎么练、拿什么当证据、哪一层做不到。

---

## 一、PID：从"知道公式"到"敢报参数"

### 会练到的 8 件事

| # | 练什么 | 具体做法 | 证据 |
|---|---|---|---|
| 1 | 固定采样周期 | TIM6 更新中断 1 kHz 里跑控制，实测周期抖动 < 5 µs | 示波器翻转 GPIO，看周期直方图 |
| 2 | 编码器测速 | 11 线 × 减速比 30 = 330 计数/圈；1 ms 窗口低速只有 0/1 个计数 → 改 20 ms 滑窗，代价是延迟 20 ms | 转速阶跃时曲线不再"台阶化" |
| 3 | 位置式 → 增量式 | 位置式 `u += Kp*e` 在切换/限幅时抖；改增量式 `Δu = Kp*(e-e1) + Ki*e` | 同样 Kp 下超调变小 |
| 4 | 抗积分饱和 | 占空比钳在 0–100%，积分项同步钳位（反算法），否则堵转 2 s 后恢复要飞车 | 堵转测试：松开后 200 ms 内回稳 |
| 5 | 死区补偿 | 实测「占空比—转速」曲线，PWM < 15% 电机不转 → 加死区前馈 | 低速 50 mm/s 能走起来不抖 |
| 6 | **电压前馈** | `占空比 = K * 目标转速 / 母线电压`，PI 只修残差 | 电压 8.4→7.2 V，转速漂移 < 2% |
| 7 | 阶跃响应测量 | 目标 200→400 mm/s 阶跃，记录 t_r、超调量、稳态误差，自动进 CAN 日志 | 一张阶跃曲线图 + 一行指标 |
| 8 | 整定流程 | 先 P 加到临界振荡，记 Ku / Tu，按 Z-N 表给初值，再按阶跃微调 | 参数表：Kp / Ki / 前馈系数 各一组 |

### 你离开时能答的问题

- 为什么用增量式而不是位置式？
- 积分饱和怎么处理？反算和钳位有什么区别？
- 前馈和反馈是什么关系，为什么加前馈 PI 就能小？
- 采样周期怎么定？定快了会怎样？
- 你说的 Kp=8，为什么不是 80？

### 诚实边界

- 做的是**速度单环 + 电压前馈**，不涉及电流环（要有采样电阻 + 运放 + ADC 同步采样）。
- 所以**不谈 FOC**，也不谈磁场定向。N20 有刷电机也用不上。
- 位置环做不了（编码器分辨率不够），只能做"走 N 米"的粗略里程。

## 二、CAN：从"会发一帧"到"会查总线"

### 会练到的 8 件事

| # | 练什么 | 具体做法 | 证据 |
|---|---|---|---|
| 1 | 位定时 | 1 Mbps：APB1 42 MHz ÷ 2 ÷ 21 = 1 MHz，BS1=15、BS2=5、SJW=1，采样点 75% | 计算表 + 实测误帧率 0 |
| 2 | ID 与优先级 | 按发送方分区：`0x100` 目标速度 50 Hz、`0x200` 动力域状态 50 Hz、`0x400` 驾驶指令 50 Hz、`0x150` 路权事件型；ID 越小越先仲裁 | 40% 负载下高优先级延迟不涨 |
| 3 | 过滤器 | F407 bxCAN 14 组过滤器，只放行本项目 ID 段；S3 TWAI 用 ADF/AFM 掩码 | 抓包只看到本项目的帧 |
| 4 | 邮箱与 FIFO | 3 个发送邮箱、2 个接收 FIFO 各 3 级；满了返回错误码而不是丢帧静默 | 满负载下不丢帧 |
| 5 | 中断 vs 轮询 | 接收走中断 + 环形缓冲，发送走邮箱状态机 | CPU 占用 < 20% |
| 6 | 错误处理 | TEC/REC 计数、错误帧、总线关闭（TEC>255）→ 128×11 隐性位自动恢复 | 拔线再插，3 s 内自行恢复 |
| 7 | 心跳与超时 | 每个节点 100 ms 一帧心跳，两帧不来就判离线 | 掉一个节点，其余节点状态机降级 |
| 8 | UDS 子集 | 0x7DF 功能寻址、0x7E0/0x7E8 物理寻址、0x10 会话、0x22 读 DID、0x3E Tester Present | 上位机敲一条命令读回固件版本 |

### 你离开时能答的问题

- 1 Mbps 怎么配出来的？采样点为什么选 75%？
- 标准帧和扩展帧的仲裁区别？
- 总线负载怎么算，70% 时会发生什么？
- TEC 到 256 之后总线上发生了什么？怎么恢复？
- 两个节点同时发同一 ID 会怎样？

## 三、电源管理：从"接个电池"到"管住能量"

### 会练到的 7 件事

| # | 练什么 | 具体做法 | 证据 |
|---|---|---|---|
| 1 | 电压电流采样 | INA226（I2C、0.01 Ω 分流、16 位），20 ms 更新 | 曲线：母线电压 / 总电流 |
| 2 | **前馈用真电压** | 采样值直接进控制器（不是"假设 7.4 V"） | 电压塌陷时占空比立刻抬 |
| 3 | 欠压保护 + 迟滞 | 6.4 V 切断驱动，6.8 V 才恢复，避免在阈值上抖 | 电压缓慢下降的测试曲线 |
| 4 | 分级上电 | 主控先起 → 自检 → 电机使能 → PWM 200 ms 斜坡软启动 | 上电瞬间没有电流尖峰 |
| 5 | 堵转检测 | 电流 > 2 A 且 100 ms 内编码器无脉冲 → 判堵转，限流 + 报故障码 | 顶住车轮，节点不复位 |
| 6 | PVD 掉电保护 | 电压跌破 PVD 阈值立刻写 Flash（里程、故障码） | 断电后重启，数据还在 |
| 7 | 低功耗 | STOP 模式约 20 µA，EXTI/RTC 唤醒 | 万用表测待机电流 |

### 你离开时能答的问题

- 电机和主控为什么必须分开供电、只共地？
- 欠压保护为什么要有迟滞？
- 启动瞬间电流尖峰怎么抑制？
- 电池内阻变大以后，同样占空比为什么转速会掉？

## 四、Linux：说清楚在哪一层，别吹过头

### 能落地的三条线

| 线 | 内容 | 交付物 |
|---|---|---|
| ① 上位机（Ubuntu） | SocketCAN（`vcan0` / `can0`）+ can-utils（`candump` / `cansend` / `cangen` / `canbusload`）+ python-can + cantools 解 DBC | 抓包脚本、负载统计、诊断脚本 |
| ② 固件在 Linux 下编译 | `arm-none-eabi-gcc` + Makefile/CMake + OpenOCD + GDB，**彻底不用 Keil** | 一条 `make` 出 .elf/.bin，一条 `make flash` 烧进去 |
| ③ 自动化 | systemd 服务开机自启、shell 汇总日志、Python 画延迟分布 | 一开机就自动记录 |

### 不能承诺的

- **不是"车载 Linux 应用开发"**。那要在 Linux SoC（T113 / i.MX6ULL / RK3568）上跑 Buildroot/Yocto，是另一条产品线。本项目不覆盖。
- 简历上只写这三条线，写准确比写大更值钱：

> 例：Linux 下用 arm-none-eabi-gcc + CMake 交叉编译 STM32 固件（OpenOCD 烧写），
> 上位机基于 SocketCAN / python-can 做总线抓包、负载统计与诊断脚本。

## 五、四块能力怎么排进里程碑

| 里程碑 | 主线 | 顺带练到 |
|---|---|---|
| M0 环境 | 工具链、烧写、串口 | ② Linux 编译链 |
| M1 CAN 打通 | 两个节点互发 | ② CAN 位定时 + 过滤器 |
| M2 单电机闭环 | 编码器测速 + 速度环 | ① PID 1–3 条 |
| M3 四轮 + 电压前馈 ⭐ | 前馈 + 抗饱和 + 死区 | ① PID 4–7 条　③ 采样与前馈 |
| M4 电源实验 | 分级上电、堵转、欠压 | ③ 全部 |
| M5 两车仲裁 | 路权状态机 + LoRa | ② 心跳与超时 |
| M6 总线三张图 + UDS | 负载/延迟/错误恢复 | ② 6–8 条　① 上位机脚本 |

## 六、诚实边界（面试可以主动说）

- 车规级 vs 教学级：用的是商用工业级器件，不是 AEC-Q100；但**问题类型是一样的**（欠压、堵转、丢帧、节点掉线）。
- 不做 AUTOSAR，不做功能安全认证，只到"知道这些概念解决什么问题"。
- 电机是有刷直流 + 编码器，不是无刷 + FOC。

> 主动说边界，比被问出来强。面试官更在意"你知道自己没做什么"。
